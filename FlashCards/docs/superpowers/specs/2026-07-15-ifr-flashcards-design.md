# IFR Written Test Flashcards — Design Spec

**Date:** 2026-07-15
**Status:** Approved pending user review
**Working name:** IFR FlashCards

## Purpose

An iPhone app for drilling and retaining FAA Instrument Rating (Airplane) written-test knowledge. The user learns concepts through a separate online course; this app's job is **retention and exam readiness** via retrieval practice, spaced repetition, and a motivating gamification layer. Success = the user (and their brother) pass the IFR written.

Two users total (the user and their brother), each on their own iPhone with independent progress, competing via a shared leaderboard.

## Decisions made during brainstorming

| Decision | Choice |
|---|---|
| Card format | Both: flip-style flashcards for recall + multiple-choice quiz mode |
| Distribution | TestFlight (paid Apple Developer account) |
| Content approval | User approved the source list; Claude generates the bank from it |
| Gamification depth | Moderate: XP, streaks, mastery, badges, daily goal + leaderboard |
| Categories | 8 topical categories, each question also tagged with ACS codes |
| Exam date | None yet; app supports setting one later |
| Architecture | Native SwiftUI, fully offline, bundled question bank, no backend |
| Leaderboard | Game Center (weekly XP, all-time XP, longest streak), shown on home screen |
| Notifications | iOS local notifications (daily reminder + streak-at-risk) |

## Question bank

### Approved sources (all FAA / public domain)

1. Instrument Rating – Airplane ACS (FAA-S-ACS-8C) — blueprint; supplies ACS codes for tagging
2. Instrument Flying Handbook (FAA-H-8083-15B)
3. Instrument Procedures Handbook (FAA-H-8083-16B)
4. Aeronautical Information Manual (AIM)
5. 14 CFR Part 61 & Part 91 (currency, rating requirements, IFR operating rules, equipment)
6. Aviation Weather Handbook (FAA-H-8083-28A)
7. FAA Chart Users' Guide
8. Airman Knowledge Testing Supplement (FAA-CT-8080-3F) — figures for figure-based questions
9. Pilot's Handbook of Aeronautical Knowledge (FAA-H-8083-25C)

Commercial test-prep banks (Sheppard Air, ASA, King, etc.) are copyrighted and will **not** be scraped or copied. All questions are original, written from the FAA sources above.

### Categories (8, topical)

1. Regulations & Procedures (Part 61/91)
2. Weather & Weather Services
3. IFR En Route Charts & Flight Planning
4. Navigation & Avionics
5. Flight Instruments & Systems
6. Instrument Approaches (SIDs/STARs/approach plates)
7. Emergencies, Lost Comms & ATC
8. Human Factors & Aeromedical

Category sizes are weighted roughly by their prominence on the real exam (regulations and weather heaviest). Target: **~800 questions at launch**.

### Question schema

Each question (JSON):

- `id` — stable string ID (survives bank version bumps; user state references it)
- `category` — one of the 8 categories
- `acsCodes` — one or more ACS codes (e.g., `IR.I.B.K2`)
- `format` — `flashcard`, `multipleChoice`, or `both`
- `front` / `stem` — prompt text
- `back` / `options` + `correctIndex` — answer content
- `explanation` — short "why," shown with the answer
- `source` — document, chapter/section, human-readable citation (e.g., "IFH 15B, Ch. 7 — Navigation Systems"), and a URL to the FAA PDF
- `figure` — optional bundled image reference (testing-supplement figures)
- `difficulty` — 1–3 tier

### Generation pipeline

The bank is generated by a fan-out of agents (one per category) writing questions strictly from the approved sources, followed by an **independent verification pass**: separate agents check each question's factual accuracy against its cited source and kill or fix anything shaky. Output is versioned JSON validated against a schema at build time — a malformed bank fails the build, not a study session.

## Study engine

### Spaced repetition

FSRS (the algorithm used by modern Anki) schedules every card. Answering updates the card's memory state and next-due date. Prefer a maintained open-source Swift FSRS package; if none fits cleanly, implement FSRS in-house (~200 lines) with unit tests against reference values.

### Review mode (flashcards) — the daily driver

- Shows all cards due today across categories (interleaved).
- Flashcards: front → flip → self-grade **Again / Hard / Good / Easy**.
- MC-format questions appear in review too, answered as real MC; results feed the same scheduler.
- New cards trickle in at a default 20/day (adjustable). Categories can be locked/unlocked so review can track the user's course progress.

### Quiz mode (exam practice)

- Pick category (or all) + length (10/20/60). MC-format questions only, weighted toward weak areas.
- **Mock exam preset:** 60 questions, real-exam category weighting, 70%-to-pass score report with per-category breakdown.
- "Review your misses" after any quiz drops missed cards into a mini flashcard session.
- Quiz misses feed the FSRS scheduler.

### Exam date

Optional. When set: per-category readiness scores use FSRS's predicted recall probability *on exam day*, and scheduling front-loads reviews in the final week so everything peaks fresh.

## Gamification

- **XP:** earned per answered card; more for harder cards, correct recalls, quiz questions. Feeds daily goal and leaderboards.
- **Leaderboards (Game Center):** weekly XP (resets Monday) is the headline race, plus all-time XP and longest streak. Custom in-app UI, not the stock Game Center sheet. No custom server.
- **Streaks:** a day counts when the daily goal is met (default: clear due reviews, min 10 cards). One streak freeze earned per 7-day streak, bankable up to 2.
- **Category mastery:** 5-level mastery ring per category, driven by FSRS predicted retention (real memory strength, not cards-seen). Doubles as the exam-readiness view.
- **Badges:** ~20 total — first perfect quiz, 7/30/100-day streaks, mastery milestones, mock exam passed, comeback-after-break, night owl/early bird.
- **Notifications (local, no server):** daily study reminder at a user-chosen time; evening streak-at-risk reminder if the goal isn't met. Deep-link into a session. Standard permission prompting.
- Out of scope: cross-device event pushes ("your brother passed you") — would require a push server. The weekly race is visible on the home screen instead.

## App structure

Four tabs:

1. **Today (home):** streak flame, daily goal ring, due count, "Start Session," and the weekly leaderboard front and center (all-time XP / longest streak one tap away).
2. **Study:** full-screen card session. Flip animation for flashcards, tappable options for MC, pinch-to-zoom figures, "Source" button expanding citation + explanation with link to the FAA PDF. Self-grade buttons after flip.
3. **Quiz:** category/length picker, mock exam preset, score report, review-misses flow.
4. **Progress:** mastery rings, readiness score, exam-date setting, badge case, stats (retention rate, cards learned, review heatmap), Game Center sign-in, settings.

**Design language:** aviation-instrument aesthetic; dark cockpit-style default theme (light theme included); instrument-face-inspired typography and accents; satisfying haptics on flips and correct answers.

## Architecture

- **Stack:** SwiftUI, iOS 17+, SwiftData (user state), GameKit (leaderboards), local notifications. Only third-party dependency: an FSRS Swift package (or in-house implementation).
- **Question bank:** read-only versioned JSON bundled in the app, schema-validated at build time. Figures bundled as images.
- **User state (SwiftData):** per-card FSRS memory state, review log, XP events, streak record, badges, settings. References questions by stable ID, so bank updates in later TestFlight builds merge cleanly (removed question → orphaned history, harmless; new question → starts fresh).
- **Offline-first:** fully functional with no network. Game Center submissions queue and retry; source links open in Safari.
- **Future-proofing:** SwiftData + CloudKit sync can be enabled later with modest effort if multi-device sync is ever wanted.

## Error handling

- Malformed bank JSON fails at build time (schema validation step), never at runtime.
- Game Center unavailable/offline: scores queue locally and submit when possible; leaderboard shows cached standings with a "last updated" note.
- Notification permission denied: features degrade silently; streaks still work.
- Timezone/midnight edge cases in streaks handled explicitly (calendar-day boundaries in the device's current timezone; tested).

## Testing

- **Unit tests:** FSRS scheduler (against reference values), streak/XP logic (midnight rollover, timezone change, streak freezes), mock-exam weighting, bank schema validation.
- **UI smoke tests:** card session flow (flip, grade, advance), quiz flow, deep link from notification.
- **Content verification:** agent-based accuracy pass over the generated bank (part of the content pipeline, not the app).

## Out of scope (v1)

- Android / iPad-optimized layouts
- Custom backend, accounts, or cross-device sync
- Server push notifications
- User-authored cards
- App Store release (TestFlight only)
- Scraping or reproducing commercial test-prep question banks
